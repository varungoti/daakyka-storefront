## Caching & revalidation map

Model in use: the **pre-Cache-Components ("Previous Model")** caching system — `next.config.ts` does not set `experimental.cacheComponents`, so `unstable_cache` + `revalidateTag`/`revalidatePath` is the correct API surface (confirmed against `node_modules/next/dist/docs/01-app/02-guides/caching-without-cache-components.md`).

| Content type | Write path | Revalidate call | Read-path cache tag | Page rendering | Updates live without redeploy? |
|---|---|---|---|---|---|
| Products | `src/lib/catalog/products.ts` (create/update/publish/archive/duplicate/bulk) | `revalidateTag(PRODUCTS_CACHE_TAG/"products", "max")` + per-slug `product-{slug}` tag, `CATEGORIES_CACHE_TAG` when category changes | `src/lib/products/index.ts` `cachedGetProducts`/`getProductByHandle` tagged `"products"`/`product-{slug}` | Mostly static (`/shop`, `/products/[handle]`, category pages) | **Yes** (SWR — next visit gets fresh data per `revalidateTag` docs) |
| Categories | `src/lib/catalog/categories.ts` | `revalidateTag(CATEGORIES_CACHE_TAG, "max")` | `cachedCategoryTree` tagged `"categories"` | Static | **Yes** |
| Site settings (shipping, sale toggle, contact info, page flags) | `src/lib/settings/index.ts` `setSetting` | `revalidateTag(SETTINGS_CACHE_TAG, "max")` | `cachedReadSetting` tagged `"settings"`, keyed per setting (Next auto-includes function args in the cache key — confirmed via `unstable_cache.md` L39: "By default, `unstable_cache` already uses the arguments... as the cache key") | Static (homepage, sitemap, robots all call these) | **Yes** — and the "fixed key array" pattern flagged in the brief (`["site-image"]`, `["site-setting"]`) is **not a collision bug**; Next hashes the actual arguments too. |
| Site images / media slots | `src/lib/media/store.ts` `saveMediaAsset` | `revalidateTag(MEDIA_CACHE_TAG, "max")` | `cachedReadSiteImage` tagged `"media"`, same args-in-key behavior as above | Static (homepage hero/tiles) | **Yes** |
| Homepage Hero/Trust-Stats/Announcement | `src/lib/homepage/index.ts` `updateHomepageSection` | **None** | **None** — plain uncached `db.homepageSection.findUnique` | Static (`src/app/page.tsx`) | **No** — F1, P0 |
| Homepage offers strip | `src/lib/offers/index.ts` CRUD | **None** | **None** | Static | **No** — F2, P1 |
| Homepage/shop/category testimonials | `src/lib/testimonials/index.ts` CRUD | **None** | **None** | Static (home) / dynamic (`ƒ /shop` per in-repo comment) | **No** on home; **Yes** on `/shop` (dynamic route re-renders every request) |
| SEO title/meta overrides (`/`, `/shop` only) | `src/lib/seo/records.ts` | `revalidatePath(path)`, gated to `WIRED_PATHS = {"/", "/shop"}` | N/A (`generateMetadata` direct read) | Static/dynamic mix, explicitly handled | **Yes**, but **only** for `/` and `/shop` — any other `SeoPageRecord` path has no live storefront reader at all (by design, documented) |
| Size charts | `src/lib/catalog/size-charts.ts` | `revalidateTag(tag, "max")` | `unstable_cache` | Product/category pages | **Yes** |
| Credential store (Razorpay/Brevo keys) | `src/lib/integrations/credential-store.ts` | `revalidateTag(CREDENTIALS_CACHE_TAG, "max")` | `unstable_cache` | Server-only reads (not a rendered page) | **Yes** |
| Reviews (moderation → product rating) | `src/lib/reviews/moderate-review.ts` | `revalidateTag(PRODUCTS_CACHE_TAG, "max")` + `productCacheTag(slug)` | via products cache | Static PDP | **Yes** |
| `/cdn/[...key]` media proxy | R2 write (`saveMediaAsset`) | N/A — served with `Cache-Control: public, max-age=31536000, immutable` since object keys are never reused | HTTP cache, not Next data cache | Route handler | **Yes** by design (new key ⇒ new URL) |

**Bottom line on the "known issue":** the underlying mechanism (Next's `revalidateTag`/`revalidatePath` on a "Previous Model" cache) is sound and, for products/categories/settings/media/size-charts/credentials/reviews, is wired correctly — the earlier observed staleness for images was plausibly from before this wiring existed on this branch, or reflects the documented one-request SWR lag (F8), not a systemic defect. However, three content types that the admin can edit directly from `/admin/homepage` and the offers/testimonials CMS — **Hero copy, Trust Stats, Announcement bar, Offers, and (on the homepage specifically) Testimonials** — have **no revalidation call at all** and sit behind a fully static homepage. Those genuinely require a rebuild/redeploy today, contradicting in-repo comments that claim otherwise (F1, F2). This is the most important, concrete, fixable finding in this audit.

*(Live verification of a save-and-observe round trip was attempted via the admin UI but blocked by the harness's shared-resource protection before the Save action; the conclusion above rests on direct code + Next.js 16 documentation analysis, which is unambiguous for this rendering mode.)*

## Verified OK (brief)

- `npm run lint` and `npm run typecheck` are 100% clean.
- `npm test`: 269/270 pass; the one failure is environment drift (F12), not a code bug.
- Hidden pages (`/mix-and-match`, `/fabric-technology[/slug]`) correctly `notFound()` when their `SiteSetting` flag is off, and `sitemap.ts`/`robots.ts` correctly gate/exclude them (`src/app/sitemap.ts` L16-30, `robots.ts`).
- `robots.ts` disallows `/admin/`, `/api/`, `/checkout`; `isIndexingAllowed()` blocks all indexing on Vercel preview deployments.
- Order-number generation (`src/lib/orders/number.ts`) is race-free: random candidate + unique-constraint retry, not check-then-insert.
- `createOrderFromCart` re-prices every line server-side from the current DB row and never trusts client-supplied price/name/image (`src/lib/orders/create-order.ts` L14-19).
- `compareAtPrice > price` is enforced on `createProduct`/`updateProduct` (not on the bulk price-adjust path — see F6).
- Cancel-stale-orders cron correctly skips stock restoration because Razorpay orders never had stock decremented pre-payment (see F11 — correct behavior, just under-documented).
- SSRF-safe image-host allowlist (`src/lib/security/image-hosts.ts`) is shared by CSP `img-src`, `next.config.ts` `remotePatterns`, and the AR try-on forwarder.
- `/cdn/[...key]` route validates path traversal (`..`/`.` segments) and serves immutable cache headers appropriate for content-addressed/UUID keys.
- `validateEnv()` (`src/lib/env.ts`) has strong, specific checks (CREDENTIAL_ENCRYPTION_KEY byte length, Razorpay all-or-nothing, admin seed password strength, HTTPS site URL) gated correctly to only hard-fail on Vercel production.
- DB pool sizing (`src/lib/create-prisma-client.ts`) is deliberately small (`DB_POOL_MAX` default 5) with a comment explaining the serverless/pooler rationale.
- Webhook idempotency: Razorpay webhook checks `order.status === "PAID"` and `razorpayPaymentId` match before reprocessing (race caveat noted in F3).
